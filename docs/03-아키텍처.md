# 아키텍처 (모듈 구조)

```
AIProCamera/
├── app/                 # Jetpack Compose UI (카메라 화면, 프로 패널, 지원정보 시트)
├── core/common/         # 공용 모델 (LensType, CaptureRecord, DeviceProfile, 로그)
├── core/camera/         # Camera2 엔진 (탐색·프리뷰·스틸·RAW·동영상·수동설정·히스토그램)
├── core/native/         # C++17 코어 + JNI (노출/화이트밸런스/히스토그램 수학) + CMake
├── core/storage/        # MediaStore 저장 + 사이드카 메타데이터 인덱스
└── docs/
```

의존성 방향은 한 방향으로 고정되어 있다.

```
app ──▶ core/camera ──▶ core/native
 │           │
 │           └────────▶ core/common ◀──────── core/storage ──▶ core/camera(MediaSink 인터페이스)
 └──────────────────────▶ core/storage
```

* `core/camera`는 **MediaStore를 모른다.** 출력은 `MediaSink` 인터페이스로만 위임한다.
  → 엔진을 파일/메모리 싱크로 바꿔 단위 테스트할 수 있고, 저장 정책 변경이 엔진에 영향을 주지 않는다.
* `core/native`의 수학은 Android/JNI 의존이 없는 순수 C++(`aipro_core.cpp`)에 있어
  **데스크톱 g++로 그대로 테스트**한다(`src/testHost/host_test.cpp`). JNI는 얇은 브리지뿐이다.

## 1. core/camera 내부 구조

| 패키지 | 역할 |
|---|---|
| `discovery/CapabilityProbe` | `CameraCharacteristics` → `CameraCapabilities`. 모든 지원 여부 판정의 단일 출처 |
| `discovery/LensClassifier` | 초점거리 + 센서 물리 크기 → 35mm 환산 → 초광각/광각/망원 분류 (순수 함수) |
| `discovery/CameraCapabilities` | 지원 정보 DTO + JSON 직렬화(기기 리포트) + `ManualControlSupport` 게이팅 |
| `manual/ManualSettings` | Pro 설정 모델(null=자동) + 하드웨어 범위로 **정규화/클램프** (순수 함수) |
| `manual/CaptureRequestApplier` | 정규화된 설정을 `CaptureRequest`로 변환 (순서: 줌 → 노출 → 초점 → WB → EV → 락) |
| `preview/PreviewTransform` | 센서 회전·디스플레이 회전·미러·채움 배율 계산 (순수 함수, UI가 graphicsLayer로 적용) |
| `engine/CameraController` | CameraDevice/Session 수명주기, 반복 요청, 스틸 캡처(AF/AE 수렴 대기), RAW(DngCreator), MediaRecorder 녹화, YUV 분석 |
| `engine/MediaSink` | 출력 추상화 (`createImageTarget`, `createVideoTarget`, `writeSidecar`, `fileSize`, `delete`) |
| `video/VideoProfileSelector` | MediaRecorder 출력 크기 선택 + 비트레이트 산정 (순수 함수) |

### 스레딩 모델
* Camera2 호출은 전부 전용 `HandlerThread("AiproCamera")`에서 수행한다.
* 공개 API는 `suspend`/`StateFlow`이며, UI는 메인 스레드에서만 상태를 읽는다.
* 프레임 콜백(`TotalCaptureResult`)이 ISO·셔터·AF/AE 상태를 `FrameInfo`로 흘려보내고,
  YUV 리더가 256빈 루마 히스토그램을 네이티브에서 계산해 같은 상태에 합친다.

### "가짜 UI 금지" 구현 방식
1. `CapabilityProbe`가 기기에서 실제 값을 읽는다.
2. `CameraCapabilities.manual`(`ManualControlSupport`)이 각 컨트롤의 노출 여부를 결정한다.
3. `ManualSettings.normalize()`가 지원되지 않는 요청을 **null로 제거**하고 범위를 클램프한다.
4. `CaptureRequestApplier`는 정규화된 값만 요청에 쓴다.
   → UI에 없는 기능은 요청에도 없다. 반대로 기기가 지원하면 UI에 자동으로 나타난다.

## 2. 저장 구조

```
Pictures/AIProCamera/
├── Original/          # 원본 (JPEG, 선택 시 DNG)
├── Enhanced/          # AI 보정본 (3단계 이후)
└── Video/
    ├── Original/      # 원본 MP4 (HEVC 우선, 미지원 시 H.264)
    └── Enhanced/      # 후보정본 (5단계)
```
* MediaStore `IS_PENDING=1`로 쓰고 완료 후 0으로 전환 → **중간에 죽어도 갤러리에 깨진 파일이 노출되지 않는다.**
* 촬영 메타데이터는 `CaptureRecord`(JSON)로 `Android/data/<pkg>/files/AIProCamera/metadata/`에 저장.
  파일 단위 JSON + `index.jsonl` 누적 → 3/5단계의 **작업 큐 재개**에 그대로 사용한다.

## 3. 네이티브 계층

| 함수 | 용도 | 검증 |
|---|---|---|
| `evToExposureMultiplier` / `exposureMultiplierToEv` | EV ↔ 선형 배율 | 호스트 테스트 |
| `clampIso` / `clampExposureNs` | 하드웨어 범위 클램프 | 호스트 테스트 |
| `sliderToDiopters` | MF 슬라이더 → `LENS_FOCUS_DISTANCE` | 호스트 테스트 |
| `kelvinToRggbGains` | Kelvin → RGGB 게인(그린=1 정규화) | 호스트 테스트(웜/쿨 방향성 포함) |
| `lumaHistogram` / `meanLuma` | YUV Y평면 → 256빈 히스토그램, 평균 루마 | 호스트 테스트(rowStride/pixelStride, null 안전) |

Kotlin 쪽 `NativeMath`는 **라이브러리 로드 실패 시 Kotlin 폴백**으로 동작하므로,
ABI가 맞지 않는 기기에서도 앱이 죽지 않는다.
