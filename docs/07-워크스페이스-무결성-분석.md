# 워크스페이스 저장 실패 분석 · 프로젝트 무결성 점검

최종 갱신: 2026-11-07

"내 워크스페이스에 1GB 정도가 저장되지 않았다"는 통지의 원인을 규명하고, 프로젝트에 실제로
빠진 것이 있는지 PC 사본과 바이트 단위로 대조한 기록이다.

## 1. 결론 요약

| 질문 | 답 |
|---|---|
| 저장 실패한 1GB는 무엇인가 | **Gradle 캐시**(`/home/user/.gradle`) — Gradle 8.9 배포본 + 이 프로젝트 의존성(AAR/JAR)·변환 캐시. **재생성 가능한 임시물** |
| 프로젝트 파일이 유실됐나 | **아니다.** 소스·테스트·문서·APK 모두 남아 있고, PC 사본과 공통 107개 파일 MD5 전부 일치 |
| 실제로 빠져 있던 것은 | **런처 아이콘**(매니페스트 `android:icon` 없음) → 이번에 추가·재빌드 검증. 그 외는 문서화된 미구현 기능들(4장) |

## 2. 왜 1GB가 저장되지 않았나

워크스페이스 스냅샷은 **약 128MB / 10,000 파일** 한도로 best-effort 저장되며, 이름이
`build`, `.cache`, `node_modules`, `dist`, `out`, `target` 등인 디렉터리는 처음부터 제외된다.
그런데 **`.gradle`, `.android`, `core/native/.cxx`는 제외 목록에 없다.**

직전 턴에 샌드박스에서 빌드를 돌릴 때 `GRADLE_USER_HOME=/home/user/.gradle`을 사용했기 때문에
Gradle 배포본과 의존성 캐시가 전부 스냅샷 대상 안에 쌓였다.

* 근거 1 — 스냅샷 이후 `/home/user/.gradle`는 **202 KB / 8 파일**로 남아 있다(캐시가 유실된 흔적).
* 근거 2 — 같은 프로젝트를 PC에서 빌드한 뒤 `~/.gradle` 규모를 실측: **8,146 MB / 66,712 파일**
  (그중 wrapper 배포본 581 MB, caches 6,573 MB — 여러 Gradle 버전·여러 프로젝트분 포함).
  단일 프로젝트·단일 Gradle(8.9) 기준으로도 **수백 MB~1 GB**가 정상 크기다.
* 근거 3 — 현재 스냅샷 대상은 **49.1 MB / 515 파일**로 한도 이내다(아래 5장).

즉 잃은 것은 **언제든 다시 받아지는 빌드 캐시**이고, 프로젝트 산출물이 아니다.
같은 이유로 샌드박스의 툴체인(`/home/user/.cache/toolchain`, 약 2.8 GB)은 `.cache` 예외 덕분에
애초에 저장 대상이 아니며, 그래서 세션이 바뀌면 **다시 설치해야 한다**(이번에도 재설치했다).

## 3. 무결성 대조 (샌드박스 ↔ PC)

방법: PC에서 `Get-FileHash -Algorithm MD5`로 전 파일 해시를 뽑아(빌드 산출물·`.cxx`·`.gradle` 제외)
샌드박스 사본과 비교.

| 구분 | 결과 |
|---|---|
| PC 소스 파일 | 110개 |
| 샌드박스 소스 파일 | 107개 |
| 공통 파일 | 107개 — **MD5 불일치 0개** |
| PC에만 있는 파일 | `.gitignore`, `app/.gitignore`(Android Studio 기본), `gradle/gradle-daemon-jvm.properties.java25.bak`(Java 25 고정 파일 백업) |
| 내용이 다른 파일 | `local.properties` 1개 — SDK 경로만 다름(정상) |

→ **소스 유실 0.** 샌드박스 사본과 빌드가 통과한 PC 사본은 동일한 코드다.
이후 기준 사본(빌드 검증)은 PC(`C:\Users\ailri\AndroidStudioProjects\AIProCamera`)로 둔다.

## 4. 실제로 "빠져 있던" 것

### 4.1 이번에 수정한 결함

| 항목 | 상태 | 조치 |
|---|---|---|
| **런처 아이콘 없음** | 매니페스트에 `android:icon`이 없고 `res/`에 mipmap도 없어 **기본 안드로이드 아이콘**으로 빌드되던 상태 | 벡터 조리개 아이콘 추가: `drawable/ic_launcher_foreground.xml`, `values/colors.xml`, `mipmap-anydpi-v26/ic_launcher(.round).xml` + 매니페스트 `icon`/`roundIcon` 지정 → PC 재빌드 성공, `aapt2 dump badging`에서 `application: icon='res/BW.xml'` 확인 |

### 4.2 문서에 이미 적혀 있는 미구현 기능 (변경 없음)

| 영역 | 미구현 항목 |
|---|---|
| 사진 | Focus Peaking, HEIF/Ultra HDR 저장, RAW 현상 파이프라인, 50MP 전량 멀티프레임 합성(현재 12MP 상한) |
| 동영상 | 실시간 **모델 추론**(GL 톤 체인까지만), OEM급 프레임 타이밍 재정렬 EIS |
| 기기 특화 | 커버 화면 자동 실행(삼성 공식 API 없음 → Labs/MultiStar 사용자 설정 필요), NPU(QNN) delegate 미탑재 |
| 안정성 | 실기기 발열 프로파일 측정, 장시간 4K 녹화 검증 |

### 4.3 테스트 공백 (정직하게 기록)

* `:core:storage`(MediaStore/Sidecar/VideoJobStore)와 `VideoPostProcessor`/코덱 경로는 **기기 또는 계측 테스트가 필요**해 JVM 테스트로 덮지 못했다.
* `:core:ai`의 모델 설치/검증은 SAF·파일시스템 의존이라 단위 테스트 범위 밖(설계 판단).

## 5. 재발 방지 (적용/권장)

| 조치 | 상태 |
|---|---|
| 샌드박스 빌드 시 `GRADLE_USER_HOME`을 스냅샷 제외 경로(`/home/user/.cache/gradle-home`)로 고정 | 적용 — `tools/build-sandbox.sh` 추가 |
| `core/native/.cxx`(스냅샷 대상) 빌드 후 삭제 | 스크립트에 `rm -rf` 단계 포함 |
| `artifacts/AIProCamera-1.0.0-release.apk`(33.4 MB, 스냅샷의 약 68%) | **PC에 더 최신 APK가 있으므로 삭제 권장** (지금은 보존) |
| 실제 빌드·검증은 PC에서 수행(샌드박스는 소스 편집용) | 적용 — `docs/06-로컬PC-빌드환경.md` 절차 |

현재 스냅샷 대상 용량: **49.1 MB / 515 파일** (한도 ≈128 MB / 10,000 파일 대비 여유 있음).
