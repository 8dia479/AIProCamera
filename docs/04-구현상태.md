# 구현 상태 · 미해결 문제

최종 갱신: 2026-11-07

## 검증 환경 구분

| 환경 | 이 환경에서 확인 가능한 것 |
|---|---|
| 샌드박스(Linux, 2GB RAM) | Gradle 빌드, JVM 단위 테스트, C++ 호스트 테스트, NDK(arm64-v8a) 컴파일, APK 패키징 |
| **실제 Galaxy Z Flip 6** | Camera2 동작, RAW 지원 여부, 커버 화면 실행, NPU/GPU 가속, 발열/배터리 **— 미검증** |

> 이 문서에서 "검증"은 **샌드박스에서 실제로 실행해 통과한 것**만 의미한다.
> 기기가 필요한 항목은 "기기 확인 필요"로 표시했다.

| 요구사항 | 상태 |

| 처리 작업 큐 | 구현 · 디스크 영속(재시작 후 재개), 일시정지/재개/재시도/취소, 발열·배터리 게이팅 |

### 4단계 — 멀티프레임 · 야간 · HDR (구현 완료 / 빌드·테스트 통과)

| 요구사항 | 상태 | 근거 |
|---|---|---|
| 멀티프레임 정렬 | 구현 (네이티브) | `multiframe.cpp: estimateShift()` — 중심 우선 블록매칭, 이동량 패널티(`0.08·|d|`)로 노이즈 오검출 억제, 중앙값 투표 + 신뢰도 |
| 야간 합성 (움직임 인식 가중) | 구현 | `mergeFrames(kNightStack)` — 3×3 국소평균으로 움직임 판정 후 프레임별 가중, 고스트 억제 |
| HDR 노출 브래킷 | 구현 | `MultiFrameMode.HDR_FUSION` → `EXPOSURE_FUSION`, AE 보정 단계로 브래킷, 밝기 중앙값 근처 합성 |
| 야간 모드 독립성 | 구현 | 야간/HDR 토글은 촬영 용도와 무관. 수동 ISO/셔터가 걸려 있으면 브래킷하지 않음(AI/자동이 수동을 덮지 않음) |
| 노이즈 지표 기록 | 구현 | `MergeStats{framesUsed, meanShiftPx, motionRatio, noiseBefore, noiseAfter}` → `MultiFrameCapture.summary`, 사이드카 `framesUsed/motionRatio/noiseRatio/alignmentShiftPx` |
| 상한 | 구현 | YUV 합성은 최대 12MP 4:3, JPEG 품질 98, 프레임당 4초 타임아웃 |
| RAW 현상 파이프라인 | **미구현** | DNG는 원본 그대로 저장(3단계). 합성은 YUV 경로만 — 문서화된 미구현 항목 |
| 50MP 전량 합성 | **미구현** | 메모리(2GB급 여유) 보호를 위해 12MP 상한. 타일 합성은 미착수 |

### 5단계 — 동영상 엔진 (구현 완료 / 빌드·테스트 통과)

| 요구사항 | 상태 | 근거 |
|---|---|---|
| 원본 녹화와 실시간 처리 분리 | 구현 | 원본은 MediaRecorder 전용 서피스로 녹화. 실시간 처리는 `LivePreviewProcessor`(EGL + OES 텍스처)로 **프리뷰 경로만** 건드림 → 실시간 처리가 켜져도/실패해도 원본 녹화는 계속됨 |
| 실시간 톤 체인 | 구현 | `ToneShaderProgram` — 스트레치·언샤프·대비·채도 (GLES2 프래그먼트) |
| 후처리 분리 | 구현 | `VideoPostProcessor` — 녹화 종료 후 별도 워커에서 실행. 원본은 이미 닫힌 파일이라 손상 불가 |
| 재개 가능한 후처리 | 구현 | 2초 세그먼트 단위 인코딩 → `VideoJobStore`에 세그먼트 체크포인트 저장 → 중단 후 이어서 진행. 마지막에 무재인코딩 remux로 `Video/Enhanced` 완성 |
| 백그라운드 실행 | 구현 | WorkManager `VideoEnhanceWorker` (고유 작업 키, 지수 백오프). 발열/배터리 보호 시 `Result.retry()` |
| 오디오 보존 | 구현 | 별도 extractor로 샘플 복사(재인코딩 없음) |
| 원본 보존 | 구현 | Enhanced는 `Video/Enhanced`, Original은 `Video/Original` 고정 |
| 후처리 톤의 목적별 차이 | 구현 | `VideoPostProcessor.toneFor(purpose, night)` — 인물은 부드럽게, 도시는 대비/채도 강하게, 야간은 최소 |
| 실시간 AI(모델 기반) 상향 | **미구현** | 실시간 경로는 GL 톤 체인까지. LiteRT 모델을 30fps로 돌리는 경로는 미착수(문서화) |

### 7차 수정 (2026-11-07, 실기기 피드백 반영)

| 보고된 문제 | 원인 | 수정 |
|---|---|---|
| 카메라 화면이 이상하게 보임 | ① `graphicsLayer { rotationZ = -degrees }`로 **반시계** 회전(카메라 버퍼는 **시계** 회전 필요) ② 뷰 전체를 회전시켜 TextureView의 스트레치와 곱해져 **종횡비 왜곡** ③ PRO 레이아웃의 `PreviewArea`가 `fillMaxWidth`만 지정돼 가중 Column 안에서 **높이 0** ④ 전면 카메라 회전식이 후면과 동일 | ① `TextureView.setTransform(Matrix)`로 교체 — 스트레치 해제 → 시계 회전 → 중앙 크롭(FILL) → 전면 미러 ② 프리뷰 박스가 **선택 비율(1:1/4:3/16:9/22:9)** 로 레터박스 ③ `fillMaxSize`로 수정 ④ 전면은 `(sensor+display)`, 후면은 `(sensor-display)` |
| 수평 고정 켜면 화면 멈춤 | 센서 콜백(≈50 Hz)이 **메인 스레드**에서 `StateFlow`를 갱신 → 매 프레임 Compose 재구성 폭주 + GL 프리뷰 스레드 경합 | 센서 전용 `HandlerThread`로 콜백 이동, GL에는 50 Hz로 직접 전달, **UI 상태 갱신은 5 Hz로 스로틀** |
| UI가 삼성 기본 카메라 같지 않음 | 검은 상·하단 바 + 텍스트 버튼 위주의 개발용 레이아웃 | 갤럭시 스타일 전면 재작성: 프리뷰가 화면 전체, 상단 아이콘(설정·플래시·비율·AI), 줌 알약, 하단 모드행(사진·동영상·야간·HDR·실시간·수평잠금), 셔터행(최근 촬영 썸네일·셔터·전후면 전환). 아이콘은 의존성 없이 Canvas 글리프로 그림 |
| (추가 요구) 화질/비율 설정 | — | `AspectRatioOption`(1:1·4:3·16:9·22:9, **가로 기준**) + `RatioSizing`: 네이티브 크기 우선, 없으면 중앙 크롭(+메타데이터 기록). 동영상은 네이티브 비율만 노출(크롭 불가) |

부수적으로 플래시 제어(OFF/AUTO/ON, `CONTROL_AE_MODE` 경유, 수동 노출 중에는 동작하지 않음을 로그로 남김)를 실제 API로 추가했다.

### 10차 수정 (2026-11-07, 10번째 피드백)

| 요청 | 처리 |
|---|---|
| 프리뷰 회전 기본값을 0° 로 | 프리뷰 회전을 **절대값 설정**으로 변경. 기본 `0°`, 선택 `90°/180°/270°/자동(센서 계산)`. 이전 "미세조정"은 내부 호출에 파라미터가 전달되지 않아 **아무 효과가 없었다**(수정) |
| 수평 고정이 빠른 회전을 못 따라감 | `HorizonFilter`를 예측형으로 재작성: 자이로(FASTEST 샘플링) 적분 + **35 ms 예측 선행** + 가속도계는 초당 45°로 제한된 보정(샘플마다 큰 가중치로 섞던 방식 제거) + 각도 언랩으로 360° 추적. 회전 시 프리뷰가 잘리는 것은 허용 범위로 처리 |
| (버그) 수평 보정이 발산 | 가속도 보정 **부호가 반대**여서 추정값이 0으로 수렴하지 않고 ±180°로 달아났다. 테스트(`disagreement ... settles`)가 잡아냄 → 수정 |
| NPU 표기 | 폰 SoC가 **SM8650(Snapdragon 8 Gen 3 for Galaxy)** 임을 확인. 하드웨어 Hexagon NPU는 존재하지만 LiteRT는 `libQnnTFLiteDelegate`/`libQnnHtp`를 번들하지 않으므로 QNN 경로는 사용 불가 → 화면 문구를 "SoC는 SM8650(Hexagon NPU 있음) · QNN 델리게이트 라이브러리 미번들"로 정정하고, NNAPI 델리게이트 가용 여부도 함께 보고 |

### 9차 수정 (2026-11-07, 실기기 로그·파일 기반 진단)

실기기 logcat과 MediaStore를 직접 조회해 원인을 확정했다. **앱이 저장한 사진이 단 한장도 없었고**(MediaStore `Pictures/AIProCamera` 항목 0건), 로그에는 2초 간격으로
`setRepeatingRequest failed: Session has been closed` 가 반복되고 있었다. 즉 카메라 세션이 계속 재생성되며 촬영이 성립하지 않는 상태였다.

| 보고된 문제 | 확정된 원인 | 수정 |
|---|---|---|
| 앱을 켜면 카메라가 안 뜨고 비율을 한 번 바꿔야 뜸 | ① TextureView가 카메라보다 먼저 오는데 `openCamera()`가 `previewSurface`를 만들지 않아 **첫 세션에 프리뷰 타깃이 없었음**(비율 변경 → 재레이아웃 → 그때서야 surface 생성) ② 레이아웃 패스마다 `attachPreviewTexture()`가 무조건 `recreateSession()` 호출 ③ 폐기된 세션 콜백이 계속 살아있어 closed 세션에 요청 | ① `openCamera()`에서 previewTexture로 surface 생성 ② surface/크기가 **실제로 바뀔 때만** 재생성 ③ 세션 세대(generation) 카운터로 stale 콜백 폐기·즉시 close |
| 비율을 바꿔도 실제 촬영 비율이 안 바뀜 | `ensureReaders()`가 **JPEG ImageReader를 카메라 교체 시에만** 재생성 → 비율 변경 시 4:3 리더로 계속 촬영하고 크롭 계획만 16:9 기준으로 계산 | 리더 생성 조건에 **stillSize 일치** 추가(비율 변경 시 리더 재생성) + 촬영 로그에 buffer/출력 해상도 기록 |
| 세로로 들었는데 90° 돌아간 사진 | HAL이 **센서 방향 픽셀 + EXIF 회전 태그**로 저장하는데, 크롭/레벨링 재인코딩 시 `BitmapFactory`가 EXIF를 무시해 회전 태그가 사라짐 | 재인코딩 경로에서 EXIF 방향을 읽어 **픽셀 자체를 정립**하고 태그 없는 JPEG로 저장(`exifRotationDegrees` + 출력 회전) |
| 수평잠금이 S26U식 360° 짐벌이 아님 | `HorizonFilter`가 ±25°로 클램프 | 클램프를 ±180°로 확장, 잠금 중에는 **창 회전을 고정**(`SCREEN_ORIENTATION_LOCKED`)하고 기기 롤 전체를 프리뷰 행렬·사진 레벨링에 적용 |
| 플렉스 모드에 새 UI 미적용 | FlexModeShell이 프로 스타일 HUD 전용이었음 | `GalaxyFlexLayout` 신설 — 상단 프리뷰 + 하단에 **동일한 갤럭시 컨트롤**(톱바/줌/모드/셔터) |
| 초광각 0.6×, 광각 1× 표기 | 35 mm 환산 최소값을 1×로 두는 방식이라 초광각이 1×로 표시됨 | `LensType` 기준으로 라벨 지정(ULTRA_WIDE→0.6×, WIDE→1×, 그 외만 환산 배율) |

## 알려진 문제 / 제약 (정직하게 기록)

1. **실기기 미검증**: 위 "기기 확인 필요" 항목. 앱의 `지원 정보` 시트에서 기기별 실측값을 즉시 뽑을 수 있다.
2. **HEIF / Ultra HDR**: 지원 여부는 조회하지만 저장 경로는 JPEG만 구현. UI에서 선택 불가(가짜 옵션 없음).
3. **RAW**: DNG 메타데이터로 직전 `CaptureResult`를 사용한다. HAL에 따라 결과 도착 순서가 달라 부정확할 수 있다 → 실기기 확인 항목.
4. **모델 미설치 상태가 기본값**: 배포 APK에는 AI 모델이 없다(설계상 의도). 따라서 기본 동작은 "고전(네이티브) 보정 경로"이며, UI와 메타데이터에 그대로 표시된다.
5. **NPU**: Qualcomm QNN delegate 라이브러리가 일반 배포 APK에 포함되지 않으므로 대부분 기기에서 "불가"로 보고된다. 이는 버그가 아니라 실측 결과이며, 필요 시 QNN 라이브러리를 추가한 빌드 변형으로 확장한다.
6. **광각↔초광각 전환**: 세션 재구성 방식이라 전환 시 프리뷰가 짧게 끊긴다(무중단 핸드오버 미구현).
7. **줌**: 디지털 크롭만 사용(광학/센서 전환 없음).
8. **동영상 실시간 AI 모델 추론**: GL 톤 체인까지만 구현. LiteRT 실시간 추론 경로는 미착수(5단계 범위 중 미완).
9. **Focus Peaking**: 미구현 (프리뷰 셰이더는 5단계에서 들어왔으나 피킹 오버레이는 미구현).
10. **메모리**: 사진 보정은 최대 4096px로 제한(초과 시 다운스케일). 50MP 원본을 그대로 처리하는 경로는 4단계에서 타일 처리로 확장 예정.
11. **발열 게이팅은 정책 수준**: 실제 발열 프로파일 검증은 기기에서만 가능.
12. **멀티프레임 품질**: 정렬은 병진 이동만 보정(회전/원근 미보정). 손떨림이 큰 장면에서는 `motionRatio`가 올라가고 사용 프레임이 줄어든다 — 의도된 동작이며 요약 문자열에 노출된다.
13. **HDR 브래킷**: AE 보정 단계(`CONTROL_AE_COMPENSATION_STEP`)를 사용한다. ±2EV를 실제로 걸 수 없는 기기에서는 자동 노출 그대로 여러 장을 찍고 합성하므로 HDR 이득이 줄어든다.
14. **동영상 후처리 코덱**: H.264로 다시 인코딩한다(HEVC 원본도 H.264 Enhanced). 세그먼트 경계에서 키프레임이 강제되어 파일이 약간 커진다.
15. **실시간 프리뷰 GL 경로**: TextureView 서피스에 직접 그리는 방식이라, 기기별 EGL 구성 실패 시 자동으로 기본 프리뷰로 폴백하고 그 사실을 메시지로 알린다(가짜 성공 없음).
16. **수평 잠금은 실험적**: OEM EIS처럼 인코더 프레임 타이밍과 센서 스트림을 재정렬하지 않는다. 프리뷰/후처리 롤 보정 수준이다.

## 13차 수정 (2026-11-08) — 1.3.4 / versionCode 15 (프리뷰 늘어남 재수정)

**왜 12차 수정으로도 늘어나 보였나**: `TextureView.setTransform()` 의 행렬이 어느 좌표계(뷰 vs 텍스처)에서
적용되는지가 모호했고, 회전이 들어가는 순간 `K·R·D⁻¹` 이 닮음변환이 아니게 되어 **비등방(늘어짐)** 이 됐다.
회전 90° + 1280×720 버퍼 + 1080×1920 창에서 `cover=1.5` 로 계산돼도 실제 렌더링은 축별로 달라졌다.

**구조적으로 불가능하게 바꿈**:
1. 비율 박스(1:1·4:3·16:9·22:9)를 `clipToBounds` 클립 창으로 사용
2. `TextureView` 크기를 **버퍼 종횡비와 동일**하게 배치 → TextureView 고유의 "버퍼를 뷰에 맞춰 늘림"이
   *등방* 스케일이 됨
3. 회전과 채움 배율은 `View.rotation` / `View.scaleX == View.scaleY` 로만 적용 → **늘어짐이 원리적으로 불가능**
4. 회전 후 크기가 박스와 같아지도록 뷰 크기를 역산(`requiredSize`)해서 채움 배율을 1.00× 로

**프리뷰 스트림 선택 변경**: 선택된 비율과 *회전 후 종횡비가 일치*하는 크기를 고른다
(16:9 → 1920×1080, 4:3 → 1440×1080). 그래서 기존의 1.5× 확대(720p → 1080 창)가 사라지고 채움 배율이 1.00× 가 된다.

**"rot 90" 은 오류가 아님**: Z Flip 6 후면 센서는 `SENSOR_ORIENTATION = 90` 으로 장착되어 있어, 세로 화면에서
세상이 바로 서려면 90° 회전이 반드시 필요하다. 설정값(기본 0°)은 그 위에 더해지는 **보정 오프셋**이다.
배지 문구를 `센서 90° · 회전 90° · 채움 1.00×` 로 바꿔 오해를 없앴다.

테스트: `core:camera` **65/65 통과** (회전 오프셋 3 + 채움 배율 3 추가).
